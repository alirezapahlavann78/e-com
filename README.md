# E-Commerce Aghaci

Monorepo for a production-oriented fashion e-commerce platform (storefront + admin + API).

## Stack
- `apps/web`: Next.js App Router storefront (catalog, CMS renderer, cart/checkout, account/orders, reviews/wishlist hooks)
- `apps/admin`: Next.js App Router admin shell + CMS pages
- `apps/api`: NestJS REST API, Swagger, JWT+refresh, RBAC, audit, rate-limit guard
- `packages/db`: Prisma schema/client/seed (PostgreSQL)
- `packages/*`: shared types/validation/utils/ui/config
- `infra/docker-compose.yml`: PostgreSQL + MinIO (S3-compatible)

## Prerequisites
- Node.js >= 20
- pnpm >= 10
- Docker Desktop (for local Postgres/MinIO)

## Local setup
1. Copy `.env.example` to `.env` and adjust secrets/URLs if needed.
   `DATABASE_URL` defaults to the bundled Postgres (`pnpm db:local`, port 55432); the Docker alternative is
   commented out. `ADMIN_BOOTSTRAP_EMAIL` / `ADMIN_BOOTSTRAP_PASSWORD` (default `admin@aghaci.local` /
   `Admin@12345`) are the credentials the seed creates for the admin panel.
2. Start infrastructure:
   ```powershell
   docker compose -f infra/docker-compose.yml up -d
   ```
3. Install dependencies:
   ```powershell
   pnpm install
   ```
4. Generate the Prisma client, create the schema and seed (DB must be up):
   ```powershell
   pnpm db:generate                     # WASM-based generator (no binaries.prisma.sh download)
   pnpm --filter @ecom/db build         # the API consumes @ecom/db types from dist/
   pnpm db:setup                        # DDL from schema.prisma + drift repair (idempotent)
   pnpm db:seed
   ```
   `pnpm db:reset` drops and recreates the public schema when you want a clean slate.
   No local Postgres? `pnpm db:local` starts a throwaway PostgreSQL 18 on port 55432.
5. Run apps:
   ```powershell
   pnpm dev
   ```

## Verification status
Automated install/migrate/typecheck/build/runtime verification is blocked in environments where `pnpm install` cannot reach the registry. Run the local setup steps above when deps/network are available; treat migrations, seed, typecheck, and runtime smoke checks as required before production use.

## Troubleshooting
- **`[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: @prisma/client`** — harmless: `pnpm-workspace.yaml`
  declares `allowBuilds: {'@prisma/client': false, prisma: false}` on purpose. Prisma's postinstall would run
  `prisma generate` and download native engines from `binaries.prisma.sh`; this repo uses a Rust-free client
  generated by `pnpm db:generate` instead. Pull the latest `master` if the message still appears, then run
  `pnpm install && pnpm db:generate`.
- **`Account temporarily locked due to failed login attempts` (403)** — five wrong passwords lock an account
  (`AUTH_LOCKOUT_MAX_ATTEMPTS`, default 5) for `AUTH_LOCKOUT_MINUTES` (default 15). Clear it immediately:
  `pnpm user:unlock` (all accounts) or `pnpm user:unlock --email=admin@aghaci.local`. Wrong password?
  `pnpm user:passwd --email=admin@aghaci.local --password=Admin@12345` resets it, or `pnpm db:seed` re-applies
  `ADMIN_BOOTSTRAP_PASSWORD` and clears the lockout. Inspect accounts with `pnpm user:list`.
- **Payment / email / SMS configuration** — the sandbox gateway, file-based email transport and
  log-based SMS transport work with no external accounts; switch to Zarinpal / SMTP / Kavenegar from
  the admin panel or `.env`. Full command reference: `docs/commands.md`.
- **Hydration warning about `cz-shortcut-listen` on `<body>`** — a browser extension injects that attribute before
  React hydrates. Both layouts set `suppressHydrationWarning`; the message is harmless and disappears in incognito.
- **`22P05 ... has no equivalent in encoding "WIN1252"` while seeding** — the Postgres cluster was created with
  the Windows ANSI code page, so it cannot store Persian text. Run `pnpm db:reset` (the script recreates the
  database as UTF8 automatically) or `rm -rf packages/db/.pgdata && pnpm db:local:fresh` for a fresh UTF8 cluster.
  New clusters are always initialised with `--encoding=UTF8 --locale=C` and connections force `client_encoding=UTF8`.
- **`P2022` / `column Product.brand does not exist`** — the database predates the current `schema.prisma`.
  `pnpm db:setup` now detects missing columns and adds them (`ALTER TABLE ... ADD COLUMN`) without dropping data.
  After pulling schema changes run `pnpm db:generate && pnpm --filter @ecom/db build && pnpm db:setup`.
- **`Cannot find module './app.module'` from `apps/api/dist/main.js`** — stale incremental build on Windows.
  Delete `apps/api/dist` and `apps/api/tsconfig.tsbuildinfo`, then `pnpm --filter @ecom/api build`.
- **`ERR_PNPM_IGNORED_BUILDS: @embedded-postgres/windows-x64`** — pnpm blocks dependency postinstall scripts.
  Run `pnpm approve-builds` and allow the package (already listed in `pnpm-workspace.yaml`).
